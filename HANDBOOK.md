# Cafe Orelo workshop portal — Handbook
> The one place that explains how this works. Plain English. Last updated: 2026-08-20

## 1. What it is
A booking portal for Cafe Orelo workshops. Each event is its own Wagtail page with its own form, price, seat cap, Razorpay Payment Links, WhatsApp group invite, and post-payment email. Kitchen staff add events in admin — not in code. The first live event is the eggless tiramisu workshop.

## 2. How it works (the flow)
1. A guest opens an event page (or picks one from Home when more than one is live) and submits name, WhatsApp, email, and a **package** (seats + price from Wagtail, not hardcoded ₹1499 / ₹2998 / ₹4497).
2. The app writes a `PAYMENT_PENDING` row with the chosen package (name, seats, amount, that package’s Razorpay URL). The status page **Pay now** opens that package’s link once — not “pay N times” for a per-seat URL. If the event has **no packages** and the old fallback **Razorpay payment link (per seat)** is set, the previous 1-seat × N behaviour still applies. Zero packages and no fallback URL: the form is disabled (“Booking not configured”). Packages with an empty link stay hidden until the kitchen pastes one.
3. The guest pays. **PENDING becomes PAID** when (a) Razorpay POSTs to `/webhooks/razorpay/` with `payment_link.paid`, `payment.captured`, `payment.authorized`, or `order.paid`, and we match the row (reference / `TIRAMISU-…` id, then email, then WhatsApp last-10, preferring a unique PENDING row for that event), or (b) staff uses **Mark as paid**. A guest “I have paid” button does **not** flip status.
4. `confirm_paid` then sends **email (Zoho SMTP)** + **WhatsApp** with the group invite. Failures are logged; the row stays PAID. Repeats are skipped (`email_invite_sent` / `group_invite_sent`).
5. A **Vercel Cron** hits `/cron/reminders` once a day at 15:00 IST (Hobby plan cannot run hourly). If the event starts within that Event’s **Reminder hours before start** (default 24) and the guest is PAID and `reminder_sent` is false, we send the reminder email + WhatsApp (group invite again).

## 3. The parts
| Part | What it does | Where it lives |
|------|--------------|----------------|
| Public pages | Home + workshop form | Wagtail pages in `workshop/models.py`, templates in `workshop/templates/` |
| SEO / share cards | Titles, canonicals, Open Graph, JSON-LD Event | `workshop/seo.py`, `workshop/templates/workshop/base.html`, OG PNGs in `workshop/static/workshop/images/` |
| CMS | Create/copy events; edit date, packages, flyer, invites | Wagtail at `/admin/` — each **Event** page |
| Participant list | The “sheet”, filterable by event | `Registration` — Wagtail **Registrations** (CSV) and `/django-admin/` |
| Database | Pages + registrations | Neon Postgres (`DATABASE_URL`); SQLite if that is empty |
| Files | Hero images and collected CSS | AWS S3 via django-storages, or local `media/` |
| Payments | Per-package Razorpay links + webhook match + `confirm_paid` | `workshop/payments.py`, `workshop/razorpay_client.py`, `/webhooks/razorpay/` |
| WhatsApp | Confirmation + reminder (per event) | `workshop/whatsapp.py` → `POST https://vertexcrm.in/api/booking-forms/whatsapp` |
| Email | Invite after payment + reminder | `workshop/email.py` → Zoho SMTP 465 SSL (optional HTTP fallback) |
| Reminders | Hours-before window, Vercel Cron | `/cron/reminders`, `workshop/reminders.py`, `vercel.json` crons |
| Serverless host | Request/response | **Vercel** Python (Django ASGI in `portal/asgi.py`) or AWS Lambda (`handler.py`, `template.yaml`) |

## 5. How it ships (deploy)
The live web app ships on **Vercel** (`vercel.json`, `portal/asgi.py`) from the local tree with `vercel --prod`. Production hostname is **bookings.healthyome.in** (Vercel project `booking-forms`). The old URL `https://booking-forms-ten.vercel.app` still works. Set `PUBLIC_BASE_URL` and `WAGTAILADMIN_BASE_URL` to `https://bookings.healthyome.in`. Neon still holds data; S3 still holds media. Migrations are **not** run on every request — run them once against the **direct** URL (`DATABASE_URL_UNPOOLED`) from your laptop. AWS Lambda (`Dockerfile` / `template.yaml`) remains an alternate host. Reminders run on **Vercel Cron** (`30 9 * * *` UTC = 15:00 IST → `/cron/reminders`). Hobby is limited to one daily cron. The old Saturday Lambda (`ReminderFunction`) is leftover, not the production path.

## 6. Data & integrations
- **Registration row:** timestamp, event, name, WhatsApp, email, package name, seats, amount, payment link, payment id, status, WhatsApp-invite sent, email-invite sent, reminder sent, reference id.
- **Packages:** Each Event has an InlinePanel of packages (`WorkshopPackage`): name, seats included, price (₹), Razorpay payment link, optional note. Public form options come only from packages that have a link. The registration stores `package` (FK) plus a `package_name` snapshot (Wagtail may recreate child rows on publish, so the snapshot is the durable label).
- **Razorpay:** The package’s own rzp.io / Payment Link is the primary path. Event field `payment_link_url` is a **fallback** only when that event has zero packages. Unique API Payment Links are used only when there is no package/fallback URL and keys exist. Point the Razorpay dashboard webhook at `https://bookings.healthyome.in/webhooks/razorpay/` and subscribe to `payment_link.paid`, `payment.captured`, `payment.authorized`, and `order.paid`. Put that webhook’s signing secret in Vercel as `RAZORPAY_WEBHOOK_SECRET_TIRAMISU` (or `RAZORPAY_WEBHOOK_SECRET`). Do not reuse the shop webhook at `https://healthyome.in/api/shop/payments/razorpay/webhook/`. GET `/webhooks/razorpay/` (or `/webhooks/razorpay/health`) returns 200 so you can see the route is mounted; it does not mark anyone paid.
- **WhatsApp group invite:** paste the invite URL on the Event page (`group_invite_link`). Guests see **Join the WhatsApp group** on `/payments/status/<reference>/` only after PAID. Same URL is sent on WhatsApp + email.
- **WhatsApp:** we only send that event’s invite link. We never add a number to a group.
- **Email:** same invite, using the event page’s subject + body (`{{name}}`, `{{event}}`, `{{date}}`, `{{group_invite_link}}`, `{{package}}`, …). Production SMTP is **Zoho** (`smtppro.zoho.com`, port **465**, implicit SSL: `EMAIL_USE_SSL=true`, `EMAIL_USE_TLS=false`). `DEFAULT_FROM_EMAIL` is `Cafe Orelo <info@healthyome.in>`. Missing host/password does not fail the webhook — payment still succeeds and the miss is logged. If Vercel blocks outbound 465, set `EMAIL_HTTP_URL` + `EMAIL_HTTP_TOKEN` (Resend-style JSON) as a fallback; SMTP is tried first.
- **Reminders:** Event fields **Reminder hours before start** (default 24) and **Reminder message** (WhatsApp + email body) plus reminder email subject. Vercel Cron calls `/cron/reminders` with `CRON_SECRET` (`Authorization: Bearer` or `?secret=`).
- **Neon:** pooled URL for web traffic, unpooled URL for migrate.

## 7. Decisions & gotchas
- We replaced Google Form + Apps Script with Wagtail because the brief asked for a serverless Wagtail portal on Neon + S3. The guest-facing fields and payment rules are unchanged.
- Tiramisu packages are seeded (not hardcoded in the form): **1 Seat / ₹1499 / `https://rzp.io/rzp/CW6o0Mec`**, **2 Seats / ₹2998 / empty link**, **3 Seats / ₹4497 / empty link**. Empty-link packages stay hidden until the kitchen pastes a Razorpay URL. Unique API links stay available only when an Event has no packages and no fallback URL and keys exist.
- Watch out: a shared rzp.io short link usually will **not** send `payment_link.paid` with our registration id. We also listen for `payment.captured` / `payment.authorized` / `order.paid` and match by notes/reference, then email, then WhatsApp last-10, preferring a unique PENDING row. If two pending guests share a number, staff must **Mark as paid**.
- Watch out: if both `RAZORPAY_WEBHOOK_SECRET_TIRAMISU` and `RAZORPAY_WEBHOOK_SECRET` are missing, the webhook still processes (and logs an error) so shared-link payments can confirm. You must still paste the Razorpay Dashboard signing secret so only Razorpay can hit this URL.
- **Mark as paid:** Wagtail Registrations → row button, or change Status to Paid; Django admin action does the same. Webhook and Mark as paid both call `confirm_paid`.
- Watch out: webhook verification must hash the **raw** POST body. Do not re-serialize JSON.
- Watch out: `RAZORPAY_WEBHOOK_SECRET_TIRAMISU` / `RAZORPAY_WEBHOOK_SECRET` are not the API key secret.
- Watch out: Lambda must use `CONN_MAX_AGE=0` and Neon’s `-pooler` host.
- Local demo can use `RAZORPAY_MOCK=true` so you can mark a payment paid without live keys. Production uses `RAZORPAY_MOCK=false` so guests hit the real rzp.io link, not a fake “Mark as paid” page.
- Production host `bookings.healthyome.in` is always allowed in `portal/settings/serverless.py` (plus `*.vercel.app`). Do not rely only on `DJANGO_ALLOWED_HOSTS`.
- Public pages follow the **vibrant** client flyer, not HealthyOme and not the earlier muted tan/gold look: forest `#0B1F12`, lime `#A2D400`, magenta `#E2186A`, gold `#FFD54F`, take-home paper `#FFF6DC`, Playfair Display + Oswald + Great Vibes + Outfit. HealthyOme green stays on Wagtail/Django admin only (`admin.css`).
- The chef + tiramisu photo is cropped from the vibrant flyer (`workshop/static/workshop/images/chef-aanchal-tiramisu.png`). The full flyer sits beside it as `tiramisu-workshop-flyer.png`. **Home** (single-event flyer) uses that crop when no Wagtail `hero_image` is set. The right photo well is taken out of flow (`position: absolute` + `object-fit: cover` + `object-position: top center`) so the **left copy** sets the row height and the **bottom** of the photo is cropped — not stretched. A `min-height` on the portrait must not push the copy column taller. On a phone the well is a short 18rem strip, not a tall empty crop. The **Event / booking** page (`/tiramisu-workshop/`) does **not** render the chef `<figure>` — copy + cream ticket only (`align-items: start`).
- Share / Open Graph images are **1200×630** recompositions of that same flyer (`og-home.png`, `og-tiramisu.png`). Run `python manage.py render_og` after flyer art changes — do not stretch the square flyer. We did **not** invent a street address for Cafe Orelo; Event schema uses the venue name only.
- Flyer title, tagline, gold banner, take-home list (one line per item), limited-seats line, enquiry WhatsApp, group invite, and post-payment email now live on the Event page. Defaults match the tiramisu flyer so `/tiramisu-workshop/` stays the same until someone edits it.
- Seat cap is per event. Only **PAID** seats count toward sold-out. Pending links do not hold a seat.
- Watch out: `bootstrap_workshop` refreshes those CMS fields to the flyer (23 Aug 2026, 3–5 PM, Aanchal Wadhwa, ₹1499). Do not re-run it after you have customized them in Wagtail.
- Watch out: `bootstrap_workshop` creates the superuser only if that username is missing. It does **not** reset the password on later runs. Local `.env` uses `DJANGO_SUPERUSER_PASSWORD=change-me`; Vercel does not set a superuser password. Production login is the Neon `auth_user` row, not the code default `admin12345`.
- Wagtail/Django admin chrome is Cafe Orelo + Octavertex (`admin.css`, `wagtailadmin` template overrides). The real Cafe Orelo wordmark (`cafe-orelo-logo.png`) sits on a cream plate so the dark olive mark reads on the forest sidebar. The Wagtail bird, “CO” mark, upgrade banner, and “Sign in to Wagtail” title are hidden/replaced.
- Public pages use the same real logo in the shared header (`base.html`), but **without** a cream pill: `filter: brightness(0) invert(1)` turns the dark olive PNG white on forest green (transparency stays). The “good food, good mood.” tagline stays. The chef/tiramisu photo is not the logo. Admin keeps the cream plate.
- Watch out: do not put `a:link { color: var(--ho-primary) }` on the whole admin. That green (`#4b8e3d`) on the forest sidebar (`#0b3f1f`) hid Registrations / Images / Documents until hover. Sidebar labels stay cream `#F5F5DC` by default.
- Watch out: Zoho custom-domain mail uses **`smtppro.zoho.com`**, not `smtp.zoho.com`. Port 465 needs implicit SSL (`EMAIL_USE_SSL=true` and `EMAIL_USE_TLS=false` — Django rejects both True). Port 587 would be STARTTLS instead.
- Watch out: Zoho SMTP login is an **app password**, not the mailbox password. `EMAIL_HOST_PASSWORD` is Sensitive on Vercel and is never stored in the repo.
- Watch out: Zoho will reject mail if `From` is not the authenticated mailbox (`info@healthyome.in`) or an allowed alias. Keep `DEFAULT_FROM_EMAIL` as `Cafe Orelo <info@healthyome.in>`.
- Watch out: the same green link rule on `#content a:link` painted “Add an image” and other header CTAs green-on-green. Button / `.w-btn` links are excluded; CTA labels stay white / cream `#F5F5DC` on the HealthyOme green button.
- Octavertex Media credit is a shared partial (`workshop/partials/octavertex_credit.html`) on the public footer, Wagtail admin, and Django admin. On public pages the type is white and the logo is inverted so it reads on the dark green footer.
- The booking form is a **cream ticket card** in the right column of `/tiramisu-workshop/` (`flyer-split--register`: copy | ticket). There is no chef photo well on that page. Watch out: do not put the form inside `.flyer-visual` — that well uses `overflow: hidden` and a stretched portrait will clip the ticket (looks like an empty dark column).

## 8. FAQ (for the tech team)
- **How do I add a package + Razorpay link?** Wagtail → Pages → that Event (`/admin/pages/4/edit/` for tiramisu) → **Packages** → **Add Package**. Fill Package name, Seats included, Price (₹), and Razorpay payment link. Publish. Guests pay that link once for the package. Reorder with the orderable handles. A package with no link does not appear on the public form.
- **A package has no Razorpay link?** It is hidden on the public form until you paste a URL and publish. It is not sold and does not crash the page.
- **How do I add a second event?** Wagtail → Pages → Cafe Orelo → Add child page → **Event** (or copy Tiramisu Making Workshop). Set date, packages (each with its own Razorpay link), slug, WhatsApp group invite, and the email sent after payment. Publish. The booking URL is `/your-slug/`. Home shows cards once two or more events are live.
- **How do I change the workshop date or price?** Wagtail → Pages → that Event. Change **Packages** for the prices and Razorpay links guests see. Flyer copy, enquiry WhatsApp, group invite, and email are on the same page. `price_per_seat` still drives the flyer “Registration charges” bar.
- **How do I replace the chef photo?** The booking page does not show it. On Home (single-event flyer), upload `hero_image` on the Event. Leave it blank to keep the cropped client flyer. OG/share images are separate (`render_og`).
- **Where are secrets?** `.env` locally (never commit it). Vercel project environment variables in production (and Lambda if you still use SAM).
- **Why isn’t my change showing in production?** Confirm you redeployed on Vercel (`vercel --prod` from this folder) **and** ran migrate against Neon. Page edits live in the database, not the git repo. A deploy without `DATABASE_URL` can start, but workshop pages will be empty until Neon + `migrate` + `bootstrap_workshop`.
- **How do I export the sheet?** Wagtail → Registrations → Download CSV (filter by event first). Or Django admin → Registrations → select rows → “Export sheet CSV”.
- **WhatsApp didn’t send?** Confirm health `whatsapp_api_url` is `https://vertexcrm.in/api/booking-forms/whatsapp` and `whatsapp_token_configured` is true. A failed POST leaves “WhatsApp invite sent” as NO so you can retry. Test by **Mark as paid**. VertexCRM must have AiSensy/Meta keys on org `healthyome` — a 401 on the route only proves the Bearer token, not a send.
- **Email didn’t send?** Check Vercel `EMAIL_HOST` / `EMAIL_PORT=465` / `EMAIL_USE_SSL=true` / `DEFAULT_FROM_EMAIL`, and that `EMAIL_HOST_PASSWORD` is a Zoho **app password** (Sensitive). Without a host, production uses a dummy backend: payment still works, “Email invite sent” stays NO (unless `RAZORPAY_MOCK=true`). Test by **Mark as paid** on a registration — the guest should get the invite email. Check Vercel function logs for `SMTP email failed`.
- **Reminders didn’t send?** Confirm `CRON_SECRET` is on Vercel and the cron path `/cron/reminders` is in `vercel.json`. This project is on Hobby, so the cron is **daily at 15:00 IST**. The Event must have reminder hours (default 24) and the guest must be PAID with Reminder sent = NO. You can hit `/cron/reminders/?secret=…` yourself to test (do not share the secret).
- **How do I add the Zoho app password?** Vercel → Project `booking-forms` → Settings → Environment Variables → `EMAIL_HOST_PASSWORD` → edit / add as **Sensitive** for Production + Preview. Do not put it in git. Redeploy after saving.
- **Where is the Octavertex credit?** Public footer on every page, Wagtail `/admin/` (dashboard + login), and Django `/django-admin/` footer.
- **Where is the booking form?** On `/tiramisu-workshop/`, in the right column beside the flyer copy (cream card: name, WhatsApp, email, package). On a phone it sits **after** the copy and price bar. There is no chef photo on this URL. If you only see a dark empty rectangle, a leftover `.flyer-visual` well is in the markup — not a missing env var. If you see **Booking not configured**, the Event has no packages with a Razorpay link (and no fallback URL).
- **Why isn’t my CSS change showing?** Public CSS is `{% static 'workshop/css/workshop.css' %}?v=…` (now `?v=20260820-crop-home`). Bump that query if Vercel or S3 serves a cached file. Admin CSS is `admin.css?v=…` from `wagtail_hooks.py`. This is not a Neon / `DATABASE_URL` issue.
- **How do I refresh the WhatsApp / Facebook share image?** `python manage.py render_og` writes `og-home.png` and `og-tiramisu.png` from the real flyer photo. Titles and descriptions use Wagtail **Promote** (`seo_title`, `search_description`) when set; otherwise `workshop/seo.py` builds them from the Event fields.
- **What is the public OG image URL?** `https://bookings.healthyome.in/static/workshop/images/og-home.png` (home) and `…/og-tiramisu.png` (event). Cache-bust query is `?v=20260820-og`.
- **Guest paid on rzp.io but still shows pending?** Shared links often skip `payment_link.paid`. If the webhook secret is set and email/phone matches exactly one pending row, `payment.captured` can flip it. Otherwise: Registrations → **Mark as paid**.
- **Where does the guest see the WhatsApp group link?** `/payments/status/<their-reference>/` after the row is PAID, as **Join the WhatsApp group**. Paste the invite on the Event page first. PENDING only shows Pay now — “Invite appears after payment is confirmed.”
- **What webhook URL do we give Razorpay?** `https://bookings.healthyome.in/webhooks/razorpay/` (events: `payment_link.paid`, `payment.captured`, `payment.authorized`, `order.paid`). Health check: open that URL in a browser (GET) — you should see `{"ok": true, "secret_configured": …, "whatsapp_api_url": "https://vertexcrm.in/api/booking-forms/whatsapp", …}`.
- **How do I know the webhook is mounted?** GET `https://bookings.healthyome.in/webhooks/razorpay/health` returns 200. It never marks anyone paid. `secret_configured` is true when either `RAZORPAY_WEBHOOK_SECRET_TIRAMISU` or `RAZORPAY_WEBHOOK_SECRET` is set on Vercel. Unsigned posts still process if both are missing so shared-link payments can confirm.
- **What is the public booking URL?** `https://bookings.healthyome.in/tiramisu-workshop/` once DNS is pointed. Until then: `https://booking-forms-ten.vercel.app/tiramisu-workshop/`.
- **Admin CTA labels look missing?** Header buttons such as “Add an image” are green. Labels must stay white / cream — never `--ho-primary` on a `.button` / `.w-btn`. Sidebar cream labels and the Cafe Orelo cream-plate logo are a separate rule.
- **Where is the Cafe Orelo logo on the public site?** Every public page header (`workshop/templates/workshop/base.html`). It is the real PNG, CSS-filtered to white (`brightness(0) invert(1)`) so the dark olive mark reads on forest green — no cream pill. Admin still uses a cream plate on the forest sidebar; do not share public classes with admin.
- **Admin sidebar items look missing?** They were green-on-green. Labels are cream by default now. The Cafe Orelo logo lives on a cream plate because the mark is dark olive.
- **Admin login failed with `admin` / `admin12345`?** That pair is only the bootstrap **code default**. The first production user was created from local `.env` (`change-me`) and bootstrap skipped later resets. Wagtail is `/admin/`. Django admin is `/django-admin/`. Reset the Neon user with `DATABASE_URL_UNPOOLED` and `portal.settings.serverless` — do not put the live password in this file.
